# 木霊 Kodama

**Kodama** (木霊, «эхо») — приложение для изучения английского и японского языков по методу интервального повторения. Соло-проект, написанный от бэкенда до фронтенда с нуля.

🇬🇧 [Read in English](README.md)

---

## Что умеет

- Создавать колоды слов/фраз на английском или японском, учить их по алгоритму интервального повторения **SM-2** (тому же семейству алгоритмов, что и в Anki).
- Автоматически генерировать новые колоды через **LLM**: указал тему и уровень — получил готовые карточки. Генерация асинхронная, запрос не блокируется в ожидании ответа модели.
- Тренировать **произношение**: записал себя — получил оценку сходства с эталоном на речевых моделях (Whisper для японского, wav2vec2 для английского).
- Вести прогресс отдельно по каждому языку (у каждого языка своё расписание повторений), смотреть статистику и прогноз нагрузки повторений на 14 дней вперёд.
- Получать обновления интерфейса в реальном времени по WebSocket, когда фоновая задача (генерация, проверка произношения) завершается.
- Входить по email/паролю или через Google OAuth; светлая/тёмная тема.

## Почему сделано именно так

Это не CRUD-поделка «для галочки» — часть решений продиктована конкретными ограничениями, а не просто «потому что модно»:

- **Генерация через ИИ и проверка произношения работают через очереди RabbitMQ в отдельных воркер-процессах**, а не прямо внутри обработчика запроса — вызов LLM или расшифровка Whisper может занимать секунды, и ни то, ни другое не должно блокировать event loop API. Клиент узнаёт о завершении задачи по WebSocket.
- **ML-модели для проверки произношения никогда не загружаются в процессе API** — их загрузка вынесена за фабрику с отложенными (ленивыми) импортами, поэтому эту цену платит только выделенный воркер, а не основной сервер.
- **Проверка ответа — это слоёный пайплайн, а не простое сравнение строк**: нормализация (NFKC + регистр + пунктуация) → точное совпадение → нечёткое сравнение (порог подобран на реальных ложных срабатываниях, например `rain`/`train`) → LLM-арбитраж для действительно неоднозначных случаев, с кэшированием вердиктов в Redis.
- **Язык — это измерение на уровне архитектуры, а не фильтр интерфейса** — колоды, очереди повторений и статистика нарезаны по языку на уровне БД/сервисного слоя, а не фильтруются на клиенте, потому что у двух языков должен быть полностью независимый прогресс.

## Стек технологий

**Backend** — Python 3.12, FastAPI, PostgreSQL + SQLAlchemy 2.0 (типизированные `Mapped[...]`), миграции Alembic, Redis (кэш), RabbitMQ (асинхронные очереди задач через `aio-pika`/`pika`), JWT-авторизация в httpOnly-cookie + Google OAuth, Whisper и wav2vec2 для оценки произношения, Docker.

**Frontend** — React 19, TypeScript (strict), TanStack Query, React Router, Tailwind CSS v4, Motion — компоненты интерфейса написаны вручную (без UI-библиотек), визуализация данных — inline SVG, светлая/тёмная тема с проверкой контраста по WCAG.

## Архитектура

```
┌─────────────┐        REST + WS         ┌──────────────┐
│  React SPA  │ ───────────────────────► │   FastAPI    │
└─────────────┘ ◄─────────────────────── │   (api)      │
                                          └──────┬───────┘
                                                  │ постановка в очередь
                                   ┌──────────────┼──────────────┐
                                   ▼                              ▼
                          ┌─────────────────┐          ┌───────────────────────┐
                          │  worker          │          │  pronunciation-worker │
                          │  (генерация LLM) │          │  (Whisper / wav2vec2) │
                          └─────────────────┘          └───────────────────────┘
                                   │                              │
                                   └──────────► RabbitMQ ◄────────┘
                                                   │
                          PostgreSQL  ◄────────────┼────────────►  Redis
```

Бэкенд построен на тонком слое `router → service → schema → model` (без слоя репозиториев — эта абстракция пока не заработала своё право на существование). Фронтенд повторяет ту же структуру: `features/<feature>/{api, hooks, ui}`.

## Запуск локально

Нужен Docker и Docker Compose.

```bash
cp .env.example .env
# заполни .env — как минимум JWT-секрет и ключ OpenRouter API
# (сгенерировать JWT-секрет: python -c "import secrets; print(secrets.token_urlsafe(32))")

docker compose up --build
```

Поднимутся PostgreSQL, Redis, RabbitMQ, API (миграции применяются автоматически) и оба воркера. API будет доступен на `http://localhost:8001`.

Для фронтенда:

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

## Статус

Проект в активной разработке. Основной цикл (авторизация, колоды, учебный цикл по SM-2, ИИ-генерация, проверка произношения, статистика) готов и используется автором ежедневно; следующий шаг — деплой на публичный инстанс.
